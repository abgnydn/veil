veil · open source

Use any AI model
without handing it your data.

veil sits between your app and a third-party LLM. It swaps real identifiers for stable code-names before the prompt leaves your machine — and swaps them back in the reply. The model is useful; it just never learns who anyone is.

The one idea

remind alice@acme.com
about /Users/baris/q3.pdf
── pseudonymize ──▶
remind EMAIL_1
about PATH_1
… the model thinks, replies about EMAIL_1 …
Reminded alice@acme.com
about q3.pdf.
◀── reverse-map ──
Reminded EMAIL_1
about PATH_1.

The same person is always EMAIL_1 within a conversation, so the model can still reason about "the person you mentioned earlier" — it just never sees the real address, name, or file path.

Not everything is equally sensitive

veil sorts each prompt into one of four levels and treats them differently. Two rules are enforced in code, not settings:

publicgeneral knowledge
"What's the capital of France?" → sent as-is.
internalmildly identifying
"My project uses React 18." → sent as-is.
privateclearly identifying
Emails, names, file paths → pseudonymized before the wire (optionally k-anonymized, below). The model never sees the real values.
secretregulated / credentials
API keys, medical records, IDs → run on a local model only. If there's no local model, the prompt is withheld — never sent to the cloud.

Hiding in a crowd — k-anonymity

Pseudonyms hide the values, but a single prompt still says "one real person asked this." For private content you can fan the prompt out alongside look-alike decoys, with every code-name scrambled to a random number. The eavesdropper sees a crowd and can't tell which one is real:

remind EMAIL_491823 about PATH_22…← the real one
remind EMAIL_77051 about PATH_91…
remind EMAIL_310044 about PATH_5…
remind EMAIL_88210 about PATH_64…

With k=8 they have a 1-in-8 chance of guessing right. veil keeps the real answer and quietly drops the rest. (Off by default — it costs 8× the model calls.)

How it's built

A Rust engine

Does the swap-and-restore round-trip and holds the secret mapping. Runs on localhost only — it's the one part that ever sees real data.

A TypeScript shell

Sorts the tiers, talks to the model (Anthropic, Ollama, …), and streams the reply back — restoring names token-by-token as they arrive.

A name detector

Regex catches emails, paths, IPs, URLs. A small local AI model (GLiNER) catches the things regex can't: people, places, companies.

Plug-in points

Ships with an MCP server so an AI assistant can use it directly, and works with cloud or fully on-device models.

Where it stands — honestly

  • ✓ Works end-to-end. Pseudonymize → forward → reverse-map, with the secret tier fail-closed.
  • ✓ Catches names well. The detector finds ~92% of people/places/orgs on a public benchmark — recall is what matters for a privacy filter (a miss is a leak). It over-flags sometimes; that's friction, not a leak.
  • ✓ k-anonymity is real. The "which one is real?" defenses (number, order, repeatability) are closed.
  • ~ Content hiding is partial. Decoys hide the prompt's shape, but a very distinctive word in your real prompt can still stand out. Fully fixing it needs your own notes as decoys — not built yet.
The honest bottom line. veil is a strong privacy layer, not a guarantee. It dramatically shrinks what a third-party model sees, keeps the truly sensitive stuff on your device, and is upfront about its edges.
Open source under Apache-2.0. Try it: cargo run --bin veil_server, then point the TypeScript client or the MCP server at it.
